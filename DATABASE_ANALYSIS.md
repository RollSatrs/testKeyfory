# Анализ таблиц базы данных и их использование

## Обзор всех таблиц

### 1. **Admins** (`admins`)

**Назначение**: Хранение данных администраторов системы
**Поля**:

- `id` - уникальный идентификатор
- `telegramId` - Telegram ID администратора
- `password` - пароль для входа
- `created_at` - дата создания

**Где используется**:

- Авторизация админов в системе
- Создание услуг (связь через `admin_id`)
- Обработка запросов на замену материалов (`processed_by`)

**Связи**:

- `Admin` → `Services` (один ко многим)
- `Admin` → `MaterialReplacement` (один ко многим)
- `Admin` → `ExecuterServiceAssignment` (один ко многим)

---

### 2. **Services** (`services`)

**Назначение**: Каталог всех услуг, которые могут выполнять исполнители
**Поля**:

- `id` - уникальный идентификатор
- `name` - название услуги
- `description` - описание услуги
- `category` - категория услуги
- `price` - базовая цена услуги
- `required_keys` - количество ключей/материалов для услуги
- `status` - статус услуги (активная/неактивная)
- `admin_id` - кто создал услугу

**Где используется**:

- Отображение списка услуг в админке
- Назначение услуг исполнителям
- Создание заказов
- Отображение услуг в боте исполнителя
- Получение материалов для услуги

**Связи**:

- `Services` → `Material` (один ко многим)
- `Services` → `Order` (один ко многим)
- `Services` → `ExecuterServiceAssignment` (один ко многим)
- `Services` → `ExecuterPricing` (один ко многим)
- `Services` → `ServiceAccess` (один ко многим)

---

### 3. **Material** (`material`)

**Назначение**: Хранение материалов/ключей для каждой услуги
**Поля**:

- `id` - уникальный идентификатор
- `type_key` - тип ключа/материала
- `service_id` - к какой услуге относится
- `contents` - содержимое материала
- `status` - статус материала (доступен/использован/заблокирован)
- `source` - источник получения (API/ручная загрузка)
- `added_date` - дата добавления
- `used_date` - дата использования
- `order_number` - номер заказа (введённый исполнителем)
- `replacement_requested_date` - дата запроса замены
- `order_id` - к какому заказу привязан

**Где используется**:

- Выдача материалов исполнителям при создании заказа
- Отображение доступных материалов в админке
- Статистика по услугам (сколько доступных ключей)
- Запросы на замену материалов
- Привязка к конкретным заказам

**Связи**:

- `Material` → `Services` (многие к одному)
- `Material` → `Order` (многие к одному)
- `Material` → `MaterialReplacement` (один ко многим)

---

### 4. **Order** (`orders`)

**Назначение**: Хранение всех заказов в системе
**Поля**:

- `id` - уникальный идентификатор
- `service_id` - какая услуга заказана
- `executer_id` - кто выполняет заказ
- `total_sum` - итоговая сумма заказа
- `status` - статус заказа (pending/in_progress/completed)
- `payment_status` - статус оплаты
- `details` - дополнительные детали (JSON)
- `created_at` - дата создания

**Где используется**:

- Создание новых заказов через бота
- Отображение заказов в админке
- Статистика по исполнителям
- Управление статусами заказов
- Расчет заработка исполнителей

**Связи**:

- `Order` → `Services` (многие к одному)
- `Order` → `Executer` (многие к одному)
- `Order` → `Material` (один ко многим)
- `Order` → `MaterialReplacement` (один ко многим)
- `Order` → `Log` (один ко многим)

---

### 5. **Executer** (`executers`)

**Назначение**: Хранение данных исполнителей
**Поля**:

- `id` - уникальный идентификатор
- `name` - имя исполнителя
- `telegram_id` - Telegram ID исполнителя
- `rating` - рейтинг исполнителя
- `status` - статус (активный/неактивный)
- `balance` - баланс исполнителя
- `access_rights` - права доступа (JSON)
- `last_activity` - последняя активность
- `create_date_executer` - дата регистрации

**Где используется**:

- Авторизация исполнителей в боте
- Назначение услуг исполнителям
- Создание заказов
- Статистика и аналитика
- Управление правами доступа

**Связи**:

- `Executer` → `Order` (один ко многим)
- `Executer` → `ExecuterServiceAssignment` (один ко многим)
- `Executer` → `ExecuterPricing` (один ко многим)
- `Executer` → `ServiceAccess` (один ко многим)
- `Executer` → `MaterialReplacement` (один ко многим)
- `Executer` → `Log` (один ко многим)

---

### 6. **Log** (`logs`)

## Проблемы и их решения

### ❌ Проблема 1: Удаление исполнителя из услуги

**Проблема**: При удалении исполнителя из услуги в админке, изменения не отражались в боте
**Причина**: Отсутствовали API-методы для удаления конкретного исполнителя
**Решение**: ✅ Добавлены методы:

- `removeExecuterFromService()` - удаление исполнителя из услуги
- `addExecuterToService()` - добавление исполнителя к услуге
- Соответствующие API-роуты

### ❌ Проблема 2: Индивидуальные цены показывались как 0₽

**Проблема**: В боте все услуги показывались с ценой 0₽
**Причина**: Неправильное обращение к полю `price` вместо `custom_price`
**Решение**: ✅ Исправлено обращение к полю `custom_price` в ExecuterPricing

### ❌ Проблема 3: Неиспользуемые таблицы

**Проблема**: Созданы таблицы, которые не используются в коде
**Статус**:

- `ServiceAccess` - создана, но не используется
- `MaterialReplacement` - создана, но не используется

### ✅ Новые возможности добавлены:

1. Удаление конкретного исполнителя из услуги
2. Добавление исполнителя к услуге
3. Установка индивидуальных цен
4. Удаление индивидуальных цен
5. Правильная работа с ценообразованием в боте

## API Endpoints для управления услугами

```
GET    /admin/services/get                              - все услуги
GET    /admin/services/get/:id                          - конкретная услуга
POST   /admin/services/add                              - создать услугу
PUT    /admin/services/update/:id                       - обновить услугу
DELETE /admin/services/delete/:id                       - удалить услугу

GET    /admin/services/executers/:serviceId             - исполнители услуги
POST   /admin/services/assign-executers                 - назначить исполнителей
DELETE /admin/services/:serviceId/executers/:executerId - удалить исполнителя
POST   /admin/services/:serviceId/executers/:executerId - добавить исполнителя

PUT    /admin/services/:serviceId/executers/:executerId/price - установить цену
DELETE /admin/services/:serviceId/executers/:executerId/price - удалить цену
```
